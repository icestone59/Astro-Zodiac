# T24.3.1 — Swagger Bearer Integration

## Problem

T24.3 added a Bearer dependency but did not wire it into the real FastAPI
application, so Swagger could not generate an `Authorize` control.

## Fix

The actual `api_app.py` now uses:

```python
def _get_user(token: str = Depends(extract_bearer_token)):
```

and the protected routes keep using:

```python
user=Depends(_get_user)
```

This causes FastAPI/OpenAPI to expose the `BearerAuth` security scheme.

## Expected Swagger behavior

1. Open `/docs`.
2. An `Authorize` button appears.
3. Paste the fresh login token.
4. Call `GET /api/v1/me`.
5. The browser sends `Authorization: Bearer <token>`.
6. The existing T13/T19 session resolver verifies the token against the
   PostgreSQL-backed session.

No second authentication system is introduced.
