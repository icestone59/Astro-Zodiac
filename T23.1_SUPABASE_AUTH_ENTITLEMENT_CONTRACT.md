# T23.1 — Supabase Auth/Entitlement Smoke Test

## Purpose

Verify the real Supabase PostgreSQL project against the runtime persistence
contracts for:

`Register → Login → Session → Membership → Entitlement`

## What this test proves

- The remote Supabase migration history contains the T17/T19 migrations.
- A user can be persisted.
- Only a password hash is stored.
- The persisted password hash verifies the login password.
- An opaque session token is represented in DB by its hash.
- A membership grant can be persisted/read.
- T12 entitlement rules grant the feature from the persisted membership state.
- Test data is removed by default.

## Important boundary

This is a database/runtime smoke test. It does **not** call Supabase Auth/GoTrue
itself. Astro-Zodiac's current T13/T19 runtime uses its own framework-neutral
Auth contract backed by PostgreSQL. A future Supabase Auth adapter can replace
this layer without changing T12–T11 domain contracts.

## Run

From the repository root:

```powershell
$env:DATABASE_URL="postgresql://..."
python .	23_1_supabase_auth_entitlement_smoke.py
```

Do not commit the DATABASE_URL.
