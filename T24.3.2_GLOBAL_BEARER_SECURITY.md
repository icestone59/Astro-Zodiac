# T24.3.2 — Global OpenAPI Bearer Security

## Problem

The FastAPI application was correctly able to receive Bearer tokens, but the
Swagger UI did not render a reliable global `Authorize` control. The previous
implementation depended on nested security-dependency introspection.

## Fix

T24.3.2 explicitly publishes:

```text
components.securitySchemes.BearerAuth
```

and attaches:

```json
"security": [{"BearerAuth": []}]
```

to protected operations.

Swagger should therefore render one global:

`Authorize 🔒`

and send:

`Authorization: Bearer <token>`

to protected endpoints.

## Protected operations

- GET `/api/v1/me`
- POST `/api/v1/analysis/free`
- GET `/api/v1/entitlements/{feature}`

`/health`, register, and login remain public.

## Authentication implementation

The existing T13/T19 session resolver remains the source of truth. This change
only makes the OpenAPI/Swagger security contract explicit.
