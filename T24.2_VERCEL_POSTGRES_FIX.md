# T24.2 — Vercel PostgreSQL Runtime Fix

## Root cause

Vercel can load the FastAPI application, but the previous PostgreSQL auth
adapter did not match the T13 AuthRepository contract and did not match the
actual T17/T19 schema.

The previous adapter used `users.id`, while the real schema uses
`users.user_id`. It also exposed `create_user()` / session methods with a
different signature than `auth_service.py` expects.

That mismatch can cause authentication to behave inconsistently between
runtime invocations.

## Fix

`postgres_auth_repository.py` now implements the canonical T13 methods:

- `get_user(user_id)`
- `get_user_by_email(email)`
- `get_password_hash(user_id)`
- `create_user(user, password_hash)`
- `save_session(token_hash, user_id, expires_at)`
- `get_session_user(token_hash, now)`

The SQL now matches T17/T19 exactly.

## Expected runtime flow

```text
Vercel
  ↓
FastAPI
  ↓
T13 AuthService
  ↓
PostgresAuthRepository
  ↓
Supabase PostgreSQL
```

## Important

Do not add Flask just to satisfy the old `main.py`. The FastAPI entrypoint is
the intended Vercel path.

Do not add in-memory auth back into production runtime.
