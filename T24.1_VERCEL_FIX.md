# T24.1 — Vercel Python Runtime Configuration Fix

## Root cause

The previous `vercel.json` contained:

```json
"runtime": "python3.12"
```

Vercel interprets `functions.*.runtime` as a runtime identifier, not a raw
Python version. A value such as `python3.12` therefore fails validation with:

`Function Runtimes must have a valid version`.

For supported Python functions, Vercel can auto-detect `.py` files under `/api`,
so the runtime property is not required.

## Correct configuration

```json
{
  "version": 2,
  "functions": {
    "api/*.py": {
      "maxDuration": 60
    }
  }
}
```

Python 3.12 is still selected by the project Python configuration/dependency
environment; the runtime identifier should not be written as
`"python3.12"` in `vercel.json`.

## Next

1. Replace the repo's `vercel.json` with this version.
2. Commit T24.1.
3. Push the commit to GitHub.
4. Redeploy the Vercel Preview.
5. Check `/health`.

Do not add a `runtime` property to `vercel.json` unless using an officially
supported runtime identifier or a versioned third-party runtime package.
